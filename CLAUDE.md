# CSharpSense — CLAUDE.md

## What this is

A VS Code extension providing Rider-grade C# IntelliSense. The suggestion engine is a self-contained .NET Language Server (stdio, JSON-RPC 2.0). The VS Code client is a minimal TypeScript shim.

## Hard constraints (non-negotiable)

1. **Zero runtime dependencies.** No Roslyn, OmniSharp, Microsoft.CodeAnalysis, or any third-party NuGet/npm package at runtime. BCL is unrestricted (System.Text.Json, System.Reflection.Metadata, System.Xml, System.Collections.Immutable, etc.).
2. **Dev/test dependencies** (xUnit, Moq, TypeScript, @types/vscode, vsce) are allowed but must not appear in published artifacts.
3. **TypeScript client is a thin shim only.** No business logic in TS. Do not use vscode-languageclient; implement the minimal JSON-RPC Content-Length framing directly.
4. **Language support: C# 6–15.** See docs/LANGUAGE_FEATURES.md for feature/status matrix.
5. **EF Core awareness is mandatory**, not optional.
6. **The engine never touches the network.** The knowledge-pack CLI (offline tool) may; the server never does.

## Build commands

```bash
# Full build (server + tests)
dotnet build CSharpSense.slnx

# Run all C# tests
dotnet test CSharpSense.slnx

# Run a specific test project
dotnet test tests/Syntax.Tests

# Build the TypeScript client
cd client && npm install && npm run compile

# Package the extension (dev only)
cd client && npx vsce package

# Build the knowledge-pack CLI
dotnet build tools/KnowledgePack

# Run the evaluation harness
scripts/eval [--baseline <path>] [--seed <n>] [--holdout]
```

## Coding conventions

- **C# target**: net9.0 (latest LTS). Use `<Nullable>enable</Nullable>` and `<ImplicitUsings>enable</ImplicitUsings>` everywhere.
- **Immutability**: syntax nodes and symbols are immutable records or sealed classes with init-only properties. Mutation lives only in builder/workspace types.
- **Logging**: structured logging to stderr only (`ILogger` abstraction backed by a stderr sink). Never log to stdout (that channel is reserved for JSON-RPC).
- **Error handling**: no silent fallbacks. If resolution fails, log the reason (file, position, reason code) and return an explicit `Unresolved` / `Unknown` discriminated union value.
- **No dead code**: every public API has XML doc comments; remove rather than comment-out unused code.
- **TODO policy**: a TODO comment must reference a ROADMAP.md milestone ID, e.g., `// TODO(M7): bind extension methods`.
- **Testing**: golden-file tests for parser output (`.golden` files in tests/Syntax.Tests/Golden/); unit tests for all binder/resolver logic; integration tests load full fixture solutions.
- **TypeScript**: strict mode, ES2022 target, no `any` except at the JSON-RPC boundary.
- **One experiment per commit** during the improvement loop; commit message format: `[exp] <Mnn> <short description>`.

## Latency budget (configurable in `src/Server/LatencyBudget.cs`)

| Metric | Budget |
|--------|--------|
| Warm p95 | ≤ 150 ms |
| Warm p99 | ≤ 300 ms |
| Cold start (small solution, ≤5 projects) | ≤ 3 s |
| Cold start (large solution, 50 projects) | ≤ 15 s |

Latency is measured every evaluation run. Any commit that pushes p95 above budget is rejected.
